## Toolchain: Node 24, better-sqlite3 12

A fresh clone on a machine with Node 24.19 and Python 3.14 could not
`npm install`. Two unrelated things stacked up:

- **better-sqlite3 11.8 has no prebuilt binary for Node 24** (ABI 137), so
  `prebuild-install` fell through to `node-gyp rebuild`.
- That source build failed twice over. node-gyp 9 imports `distutils`, which
  Python 3.12 removed. And Node 24's headers select the **ClangCL** MSBuild
  toolset, which a default Visual Studio 2022 install does not have.

Neither is a reason to hold the project at Node 20. The fix that needs no
compiler at all: **better-sqlite3 `^12.4.1`** (resolved 12.11.1), the first
line that publishes both the `node-v137` and the `electron-v130` (Electron 33)
Windows binaries. 12.0's only breaking change is dropping Node 18 and
Electron 26–28, neither of which we use. No API change.

Alongside it the project now says Node 24 everywhere it said 20:

- `.nvmrc` → 24; `engines.node` → `>=22` (better-sqlite3 12's own floor).
- The four workflows (`ci`, `release`, `pr-eval`, `pr-eval-report`) → Node 24.
- CONTRIBUTING prerequisites and the README install comment.

Verified on Node 24: `npm install` (postinstall rebuilds for Electron 33 —
confirmed by loading better-sqlite3 under `electron.exe` with
`ELECTRON_RUN_AS_NODE`), both typechecks, `npm run build`, and the suite:
**623 tests across 65 files pass, 1 skipped.**

Two Electron binary downloads aborted mid-transfer (`ECONNRESET`) during the
retries; that was the network, not the toolchain — a plain re-run finished.

Not committed yet; changes sit on the working tree.

## In-session history: question N now knows about question N-1

User report: during a meeting the session "doesn't remember the past
questions". Traced, and it was structural, not a window size: `streamAnswer`
received the current question plus retrieval and nothing else. Every cue was
a fresh two-message Responses call, no `previous_response_id`, no transcript
window, no earlier Q&A. The only rolling buffer in the engine
(`AmbientTriggerPolicy.recent`) feeds the salience *classifier* and never the
generator. Meetings felt worst because every answer there is a summon, so
"what about the second option?" arrived with no first option in sight.

Fix, kept prompt-only so the DB rows stay the record:

- `EngineSession.history` — `heard` turns (pushed in `onTranscriptFinal`,
  clipped to 300 chars) and `asked` question/answer pairs (pushed when a
  stream completes, answers clipped to 700), 10 items max. A regenerate
  updates its entry; a detected question replaces the `heard` turn it came
  from; the question's own turn is excluded from its snapshot
  (`historyBefore`), which the first version got wrong and the tests caught.
- `GenerateInput.history` → forwarded by interview and meeting modes →
  `AnswerInput.history` → one `EARLIER IN THIS CONVERSATION` block right
  before `QUESTION:`, told to resolve references and never cite or restate.
  Absent history leaves the prompt byte-identical (pinned by a test).
- Retrieval: a follow-up of ≤ 8 words embeds together with the previous
  question, so "and why that one?" retrieves about the thing, not about
  "why".

Tests: three parity cases (first question has no history, second sees the
first exchange once; heard turns + the retrieval query; regenerate updates in
place) and two prompt cases. Documented in `06-OPENAI-SERVICE.md`.

## Question detection in meetings — a design, not a crash (not changed)

Second report: "question detection is not working". In meeting mode the
interview classifier is never called at all: `meeting.mode.ts` stubs the
trigger to `act: false`, and a turn the heuristics call a *question* is
**held** (`ambientPolicy.ts` `question-held`) until two further substantive
turns arrive and neither "answers" it — where "answers" means sharing one
non-stopword. Then it still has to clear the `quiet` presence floors (0.75
for `open_question`) and cooldowns (one card per 90 s, one per kind per
180 s), and a session-lifetime dedupe. The acceptance suite runs at
`balanced`, not the shipped default `quiet`. Net: a spoken question in a
meeting almost never produces anything, by design. Options written up for
the maintainer; no behaviour changed here.

## Transcription latency + local STT — findings for the brainstorm

Live path is OpenAI Realtime `gpt-4o-transcribe`, server VAD with
`silence_duration_ms: 600`, `near_field` noise reduction even for system
loopback, PCM 24 kHz through a deprecated `ScriptProcessor(4096)` (~170 ms
frames, one IPC + base64 per frame, a Zustand set on every callback), and the
pipeline acts only on *completed* turns — deltas paint the interim line and
nothing else. No local STT exists in code; `5.6b` on the board is the
whisper.cpp spike. Recommendation recorded in the session summary: the
sherpa-onnx runtime with NVIDIA's cache-aware streaming models
(`nemotron-speech-streaming-en-0.6b`, `nemotron-3.5-asr-streaming-0.6b`),
INT8 ≈ 630 MB each, downloaded on first use — not whisper.cpp.
