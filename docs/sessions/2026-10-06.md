# 2026-10-06

## Local engine clipped the first word of a turn (rule 1 endpoint)

User: "live transcription is not good — are we on the local model?" Yes:
`stt_prefs` in the installed app is `local` / Nemotron EN. Their transcript
rows showed the symptom: opening words missing ("We have until…" → "Until…",
"Right, that's the line" → "That's the line"), while the microphone's echo
copy of the same turn was complete.

Experiment (`scratchpad/turns-exp.mjs`, ten turns from the user's own demo
lines, Windows SAPI voices because the `.env` OpenAI key now returns 401; fed
straight into sherpa-onnx at the app's frame size with the app's resampler):

| config | gaps 0.8–4.5 s | gaps 2.5–6 s |
| --- | --- | --- |
| A current: rule1 2.4, rule2 1.4 | 1 short turn lost entirely | **2/10 opening words clipped** ("Fine,", "Morning.") |
| B rule1 off (60), rule2 1.4 | 10/10 intact | **10/10 intact** |
| C rule1 off, rule2 1.0 | more splits, no clipping | — |
| D never reset, segment by text diff | 3/10 clipped, fragments | — |

Cause: sherpa-onnx rule 1 fires after N s of silence with no text and
`reset`s the stream; in a quiet call that reset coincides with the first word
of the next speaker. A silence-only segment produces no final, so the rule did
nothing useful for us. Fix: `rule1MinTrailingSilence: 60` in `stt/worker.ts`
(rule 2 stays 1.4 s — turns closer than that merge into one final, the trade
for not cutting sentences, per the 2026-09-07 finding). Docs 22 updated;
changelog line under 2.2.0 *Fixed* (the draft release is unpublished — the
v2.2.0 tag still points at the pre-latency commit, so either the tag moves or
this ships as 2.2.1; user's call).

Also noted: the `.env` OpenAI key is rejected (401) as of today, so cloud
paths cannot be live-tested from this machine until it is replaced. The
installed app has its own encrypted key.
