# 2026-07-29

## Cleanup, and saying out loud what the product is

The product changed under the documentation. Everything user-facing still led
with a **mode catalog** — the README's first table, the landing page's third
section, the vision doc's §3, the onboarding tour's step titles — while the app
itself hasn't asked anyone to pick a mode since the activity work landed. That
is not a cosmetic mismatch: a mode picker is exactly the thing that was deleted
for being the same question asked twice, and the front door was still selling it.

### The bug the sweep found

`HomePage` called `api.session.list()` with **no profile id**. Home greets you
by name and then listed every profile's recent calls underneath the greeting.
The same class of leak was fixed in Sessions and Insights a day earlier; this
was the one that got missed, because `profileId` is *optional* on that channel —
main also serves the overlay and the DB explorer, which legitimately want
everything — so omitting it is not a type error.

`profileScope.test.ts` now scans the renderer source and fails on a bare
`api.session.list()` / `practiceStats()`. Writing it caught something worth
recording: **the first version of the guard did not catch the bug it was written
for.** The real call is formatted across three lines by prettier
(`api.session\n  .list()\n  .then(...)`), and a regex assuming one line matched
nothing at all — a guard that passes because it never looks. It now tolerates
whitespace between every part, and one of its two tests asserts both shapes.

### The rest of the sweep

- **Dead code:** `components/Waveform.tsx` — nothing had imported it in a long time.
- **Mode names in user-facing copy:** the route title "Interview Copilot", the
  live banner's `Meeting Copilot is live` fallback, Home's Labs strip, and four
  tour step titles. All now name the *activity*. `ModeCard` → `ActivityCard`,
  and the `data-tour="mode-*"` anchors → `activity-*`.
- **A tour step that was simply wrong:** step 3 told new users the Library holds
  "its Memory". Memory moved out of the Library into its own nav section. It now
  describes what a Space actually is, including that it is where a conversation
  is kept.
- **"Prompt N" labels** stripped from source and design docs (they described a
  build order nobody reading the code cares about). Left in `docs/sessions/`,
  which is a diary of what happened on a given day — rewriting that would be
  rewriting history rather than cleaning up.

### Sample data stopped being an interview demo

"Load sample data" seeded one résumé and three job Spaces, so the first thing a
new user saw said *this is an interview tool* before they had done anything. It
now leads with a recurring **meeting** Space (Tuesday standup — Atlas, with a
real agenda) and seeds one finished, **unkept** conversation in it.

Unkept on purpose. Fabricating an archive and a couple of approved memories
would have been easier and would have lied: it would show the output of a
decision the user never made. Leaving the conversation sitting there means
pressing Keep runs the real pipeline — summarise into the Space, propose
candidates — and that is the thing worth seeing.

It also unblocks the demo video. `media.capture.spec.ts` gains two scenes:
the review queue *before* anything is approved, and the same page after one
click. Proposed → approved is the entire difference between a suggestion and
something that will be recalled, so it is two frames, not one. Memory is
consent-gated off, so the spec turns it on explicitly first — the same switch a
user flips — and both scenes drop out of the manifest if extraction returns
nothing, rather than rendering blank.

### Docs, README, website

- **README** leads with the activity table and a Spaces/memory section, with the
  summary-vs-memory difference as a table. The old mode table is gone.
- **Landing page**: §3 "Modes are presets" → "You say what the call is", and a
  new §4 on continuity — what a Space is, and the two things kept in it. A "How
  v2 works" column joins the docs grid.
- **00-VISION §3** is now an activity catalog that names the mode each one runs,
  with a dated note explaining that it used to be a mode catalog and why that
  changed. Principle 6 was rewritten: continuity is scoped, and memory belongs
  to the user.
- **11-UX-NAVIGATION** had two supersession notices at the *bottom* of a document
  whose title and first 190 lines were written mode-first. The banner is at the
  top now.
