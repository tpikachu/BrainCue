## M7.2b evidence tooling — review corrections (`feature/interview-copilot-first`)

Continues [2026-11-18](./2026-11-18.md). Codex accepted `c9d225b` (the
"Tell me about…" prefetch). `74f12cd`'s live tooling needed three
corrections before the live plan can be approved. Each reproduced offline on
the actual `74f12cd` driver code:

- **A late record became the next fixture's sample.** The collector took
  the newest row of the latency file. Records are now attributed by the
  question the app detected, or by the time window of their final when there
  is no text (`bench/perf01.collect.ts`). The driver waits for earlier
  answers to finish before the next question.
- **Invalid evidence could read "met".** The report counted rows. A live
  report is now judged only after the folder is checked against the run's
  manifest (`bench/perf01.evidence.ts`): blocks, fixtures once each, cold
  processes, route and effort, grounding, decision summaries, and the
  budget. Anything else makes every verdict "invalid evidence". A live run
  never falls back to question-only decision times.
- **The token cap could be exceeded.** It was checked only before a question,
  and on answer usage only. A meter in main (`scripts/perf01/live-meter.cjs`)
  now reserves every provider request's upper bound before sending it,
  across processes, and refuses past the caps. That covers setup, the
  classifier, predictions, embeddings, retries and speech-to-text seconds.
  The driver checks a question's worst case before asking it and stops on a
  cap. The per-question reserve is measured: the offline benchmark records
  every answer request's reservation and fails if one exceeds it.

Also:

- **Setup runs once.** Each block is a fresh process on a copy of it, so
  setup is no longer repeated twelve times.
- **Preflight.** Each block checks the pinned route, the speech-to-text
  model and VAD (from the session's own configuration), and both windows
  visible on the second monitor.
- **Meter loading.** The meter loads only in main, not in its worker
  thread: the dry run showed `--require` reaching the privacy worker too.

Revised plan: docs/benchmarks/PERF01-LIVE-PLAN.md. **Not run live.**

## M7.2b evidence tooling — second review corrections

Codex kept `492a6cc`'s fixes and found three more gaps. Each reproduced
offline on the `492a6cc` code before the fix:

- **A failed preflight passed its test.** The block returned early, and the
  serial suite could go on to paid blocks. The driver logic now lives in
  `bench/perf01.driver.ts`, behind an `AppPort` the spec implements over
  Playwright and the tests implement over a fake app. Every unsuccessful
  block saves its evidence, stops its session, then fails. No later block
  of the run starts.
- **An old take could stand in for its running replacement.** A record is
  written only when a take finishes, so an answered take 1 sat in the file
  while take 2 ran. The driver now watches each card's latest announced
  take (`latencyTake`) in the Cue Card page. A question is finished only
  when its current take is, for collection and for settling. Each block's
  lines are reconciled at its end from all the raw records, with that
  take's own context for grounding.
- **The report ignored the manifest's caps.** The run is now bound to one
  configuration: a reused folder is refused. The meter's installed caps are
  checked before the seed and every block spends. The report rejects:
  - totals over the caps;
  - processes with other or no caps;
  - missing or extra metered processes;
  - a ledger that disagrees with its request log;
  - any refused request.

**Not run live.**

## M7.2b evidence tooling — registration fix

Codex accepted `e7a268b`'s three fixes and found one more gap. The dry-only
test asked for the app fixture and skipped inside its body, so Playwright
launched an app first. In a live run that was a metered process belonging to
no block, and the coverage check would reject an otherwise complete paid
run. The reverse happened too: dry runs launched an app for each of the 12
skipped blocks.

Registration now lives in `e2e/perf01-register.ts`: only the active mode's
tests are registered. `e2e/perf01-register.spec.ts` (offline tier) runs it
under Playwright with a fake app fixture, in live, dry and no-key modes. It
failed on the old shape (live: +1 launch; dry: +12) and passes now. The dry
run now shows 2 tests and 2 metered processes. **Not run live.**
