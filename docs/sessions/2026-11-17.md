### 1 · Detection + scheduling
Rules decide reliable cases with no model call; the classifier (context, zod,
1.2 s timeout, 5 s late verdicts) decides the ambiguous rest. Explicit
scheduling policy: detect always, one stream at a time, FIFO queue, coalesce
repeats, supersede continuations/corrections on the same card, hold
fragments, missed cards instead of silent drops. "Answer that" button.
Latency instrumentation incl. first VISIBLE content (overlay reports after
paint) → `<userData>/metrics/latency.jsonl`.

### 2 · Context + grounding
`ConversationContext` replaces the history buffer (recent verbatim, compact
earlier record, BM25-recalled turns, open questions, suggestions labelled as
not evidence, referential subject). Follow-ups follow what the candidate SAID.
Resume restores the session's own rows. Prompt ranks sources, labels JD as
employer requirement, treats documents/transcript as data. Résumé/JD source
balance in retrieval.

### 3 · Models + readiness
Provider + Fast/Balanced/Quality → per-task candidates filtered by discovery
(cached `/models`). Catalog capability metadata (efforts, thinking, lifecycle);
live tasks at the lowest effort ("none" on GPT-6). Overrides preserved,
corrected only when they cannot run. One bounded retry before the first token;
unavailable model → next candidate on the same provider. Per-capability
readiness; no OpenAI key required to start; parsing on any chat provider;
lexical retrieval without embeddings; vector read path now identity-filtered.

### 4 · UI
Interview default + first; readiness checklist in the start modal; Cue Card
trimmed (extra controls behind ⋯, compact transcript, duplicate companion bar
and memory editor removed); capture status in the Cue Card.

## Review round 1 → milestone M1 (reliable interview startup)

Codex's review (changes required) was turned into an acceptance sequence on
the board (M1–M7, one milestone per handoff). M1 is handed off alone:

- `useLiveSession.startNew/resumeExisting` return an explicit `StartResult`;
  failures roll back (tracks stopped, session stopped, a new one deleted, its
  save prompt suppressed). Capture status is reported only after the audio
  pipeline is attached. The start modal stays open on failure.
- Regression tests (9). Against the OLD store 8 fail: the attach/IPC/no-audio
  rollbacks, report-after-attach, an already-ended track, and the explicit
  result for partial capture (whose notice text was already right). The
  mid-session track-ending test passes on both — it guards existing behaviour.
  Cases:
  no audio, picker cancelled / no mic (partial capture names the missing
  stream), session IPC failure, attach failure (new and resumed), a track
  already ended during setup, a track ending mid-session.
- Work for M2–M5 written in the same round is parked on local branches
  (`park/m2-providers` … `park/m5-home`) until their gates open.

### M1 review round 2 (`f0ae681` → changes required)

Two blockers fixed in the rollback of a failed start:
- The save-prompt suppression was a process-lifetime set, so a failed resume
  silenced every later save prompt for that session. It is now one-shot —
  set only while the rollback's own stop runs.
- Stop/delete errors were swallowed and reported as "The session was
  stopped". Now only confirmed steps are claimed; a rejected stop keeps the
  session visible (`cleanup: 'failed'`) and Stop retries the same rollback;
  nothing is deleted before the stop is confirmed.
- 6 new regressions (fail on `f0ae681`): fail→succeed→stop prompts for a
  resumed and a new id; rejected stop for new and resumed sessions, with a
  confirmed retry; a retry that fails again; stop OK but delete fails.

## M2 — provider selection that stays consistent

M1 accepted at `fc7571c`. M2 started from the parked commit and was completed
against the board's acceptance criteria:

- Overrides pin their task to their provider: an unavailable model falls back
  within that provider; a keyless override is kept (readiness blocks with the
  fix) instead of moving to the chat provider. The live answer retry refuses
  any route on another provider.
- Parsing, briefs, stories, the report, mock questions and sparring feedback
  run through the routed provider (`chatTask.ts`) with the same bounded
  failover (one same-provider retry on a model error, never after a token).
  Tailoring is pinned to an OpenAI model and gated on the OpenAI key.
- `readiness.features` (parsing / practice / tailoring) replaces the
  OpenAI-key checks in the profile editor, Story Bank, Mock and Sparring.
- Tests run the real policy/models/registry/routing with faked vendor
  adapters: multiple keys, Anthropic-only, overrides (valid, unavailable,
  keyless), unavailable models, at-most-one retry, auth not retried, partial
  streams, per-feature gates.
