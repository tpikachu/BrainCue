# 2026-11-24

## Stable 2.3.0 release

The user asked for a **stable** release rather than another preview, so
that installed apps update automatically. They chose to ship the last
Codex-reviewed source, `1c89664` (CI green), and leave the two later,
unreviewed speed commits (`8406cde` connection pool and warm-ups, `2b5bfbe`
diagnostics corrections) for 2.3.1.

The release branch `release/v2.3.0` starts at `1c89664` and adds only:

- the version, `2.3.0`, in `package.json` and `package-lock.json`;
- `changelog/2.3.0.md`, covering everything since 2.2.2, because stable
  users skip the preview;
- the board's S3 row and this log.

**Speed is released with a known gap.** The measured synthetic Fast run
missed both medians (about 2.4 s against 1.5 s) and Technical p95 (4.6 s
against 3 s). The changelog says so under *Known limitations*, and PERF-01
stays open. The release changes no product code.

**Auto-update.** The release workflow builds Windows, macOS and Linux
installers and publishes them, with `latest*.yml`, to a draft release for
the tag. Once the draft is published as the latest stable release,
installed 2.2.x and 2.3.0-preview.1 apps find 2.3.0 and download it
automatically (`autoDownload`). A preview build follows prereleases by
electron-updater's default, and 2.3.0 is newer than 2.3.0-preview.1.

Release steps 2–4 of the ritual (roadmap, board reset, milestone) are left
to Codex.
