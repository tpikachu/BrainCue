# 2026-10-07

## Answer styles: General | Technical replace five formats + the type dropdown

User decision: the Cue Card's two answer controls — the TYPE dropdown
(general / behavioral / technical / coding / system design) and the five-way
FORMAT control (key points / explanation / detailed / story / STAR) — were too
complex to operate mid-sentence. Keep the app easy and clean; everything that
can be automatic should be; performance matters (no extra model calls, modest
token ceilings).

### What changed

- **One two-way chip** on the Cue Card: **General | Technical**
  (`renderer/overlay/controls/AnswerControls.tsx`). The TYPE dropdown, the
  FORMAT segmented control and their props (`onChangeType`, `INTERVIEW_TYPES`)
  are gone. Kept: model chip (task still via `pickerTask(interviewType)`),
  listen-only toggle (coding only), history, pronunciation, clear.
- `AnswerFormat` (`shared/types.ts`) is `'general' | 'technical'`.
  - `general`: one bold lead sentence that answers directly, then 3–4 short
    bullets (reasons / next steps). ~120 words. `max_output_tokens` 360.
  - `technical`: same lead, then 4–6 bullets that may hold specifics (names,
    numbers, a line of code), then one short paragraph on approach and
    trade-offs. ~200 words. `max_output_tokens` 600. (+160 for pronunciation,
    as before.)
- **Behavioral story shape is automatic.** `streamAnswer` takes an optional
  `questionType`; under the interview framing, `'behavioral'` appends one
  sentence to the FORMAT instruction (situation → what I did → result, first
  person singular, most specific outcome the context supports, never an
  invented one, no labels). Threaded `EngineSession.answerQuestion` (`q.type`)
  → `generateContribution` → `mode.generate` (`GenerateInput.questionType`) →
  `interview.mode` → `streamAnswer`. `LastQuestion` keeps the type and
  `enginePersistence.question(id)` returns `{ text, type }` so a regenerate
  (per-card or last) re-sends it. Meeting mode (conversation framing) is
  unaffected.
- **Legacy values keep working.** `normalizeAnswerFormat(v)` in
  `shared/types.ts`: key_points / explanation / story_teller / star → general,
  detailed → technical, anything else → general. `zAnswerFormat` is now a
  `z.preprocess` over that normalizer, so `session:start`, `session:resume` and
  `session:set-answer-prefs` accept old strings. `engine.setAnswerPrefs` also
  normalizes before storing.
- **Overlay** (`Overlay.tsx`): the chip's `changeFormat` sets `answerFormat`,
  calls `setAnswerPrefs({ format, interviewType })` — Technical →
  `interviewType: 'technical'`, General → `'general'` — **unless** the session
  is `coding` (then only `format` is sent; a coding session stays coding), then
  regenerates the open question. The old `changeInterviewType` handler is
  removed.
- **Coding solver** (`codingPrompt.ts`): `CODING_DELIVERY` has two entries —
  general = the former "explanation" spoken walkthrough, technical = the former
  "detailed" text. Default param `'general'`; `codingMode.ts` fallback
  `'general'`.
- **Defaults** `'key_points'` → `'general'` everywhere (engine start / resume /
  prefs, sessionManager, preload, session.ipc, mockManager, InterviewPage,
  TailorPage, StartSessionModal — companion included — Overlay initial state).
- Docs: 05 (enum + legacy mapping), 06 (two styles, ceilings, `questionType`,
  behavioral auto-shape), 11 (Cue Card controls), 12 / 20 / 21 / README stale
  mentions. docs/04, 16, 17 mention the STAR *story bank* (a retrieval
  feature), not the answer formats, so they were left alone.

## Follow-ups in interviews ("what was your role there?") + save dialog

User report: after "Tell me about your last project and what was your role?",
the follow-up "Well, what was your role there?" got an unrelated answer.

Plumbing checked: interview mode does pass `history` into the prompt and a
≤ 8-word follow-up already carried the previous question into retrieval. Two
weak spots fixed:

- **Prompt.** The history header told the model only to "resolve references";
  it now says a short follow-up CONTINUES the last exchange — "there / that /
  your role" means the subject of the last answer — and never to switch
  project or example unless the question names one.
- **Retrieval.** The follow-up's query carried the previous *question* but not
  the previous *answer*, and the answer is where the project was named.
  `retrievalQuery` now adds the first 240 chars of the previous answer.
  Tests in `answer.test.ts` and `engineSession.prefetch.test.ts`.

Verified live (fresh `.env` key, built app in E2E mode, interview session,
`session:ask` x3 against a two-project resume — Orion/tech lead at Acme,
Helios/backend at Beta Labs):

| Question | Answer stayed on | First token |
| --- | --- | --- |
| "Tell me about your last project and what was your role?" | Orion migration, lead | 4.0 s |
| "Well, what was your role there?" | Orion — "technical lead, architecture, five engineers" | 1.8 s |
| "And what was the hardest part of it?" | Orion zero-downtime cutover | 1.2 s |

No drift to Helios on either follow-up. Harness: scratchpad `followup-live.mjs`.

Also removed the "What kind of interview was this?" select from the
end-of-session save dialog (`SavePromptModal.tsx`) — the five-type list the Cue
Card no longer has. The session keeps the type the chip set.

Branch hygiene: post-2.2.1 work moved to `feature/v2.2.2-cue-card-and-transcript`
(created from the two commits that had landed on the merged release branch).
