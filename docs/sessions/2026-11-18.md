## M7.2a correction 2 — dashboard drafts survive settings pushes (AI-02)

**Problem.** `ModelsCard` reset its whole `overrides` draft and cleared
`dirty` whenever `settings.models` changed identity, and main sends a fresh
map with every push. As a result:

- An unrelated push (discovery, failover, another window's write) wiped an
  unsaved choice.
- `<details open={customized}>` then closed Advanced.
- Save wrote `{ modelOverrides: {} }` and said "Models saved."

**Fix.**

- Incoming snapshots refresh only the tasks not edited in the card.
- `dirty` maps each edited task to the sequence number of its edit. A
  confirmed Save clears a task only if it was not edited again meanwhile.
- A failed Save keeps the drafts and says so. An empty Save writes nothing
  and says so.
- Advanced is user-owned: it opens when overrides are active, and a push
  never closes it.

`modelsPanel`). All 4 fail on `084cd07` (worktree via `HARNESS_ROOT`, since

## M7.2b — interview latency (PERF-01): instrumentation and the answer path

**Instrumentation first.** The latency record now keeps each stage on its own:

- speech end → final, with which anchor it is;
- detection;
- queue wait;
- waiting for context, with retrieval and recall run times;
- provider first token;
- first useful paint;
- completion.

Every detected question ends with an outcome, and failed and missed ones are
kept in the sample. Results are split into General, Technical and coding,
each cold and warm.

The renderer used to report the first nonblank chunk, often a bare `**`. It
now reports the first painted real word. The `metrics:first-visible` channel
is renamed `metrics:first-useful`.

**Diagnosis.** Memory recall embedded the question a second time, in series
after document retrieval, and was never prefetched. The live embedding also
used the indexing client's retries and 60 s timeouts, so one stalled request
held the answer for seconds.

**Changes:**

- Documents and memory are gathered in parallel, starting on the interim.
- One shared query embedding serves both.
- The embedding has a 2.5 s cap with a lexical fallback over the same
  documents.
- Recall no longer drops all memories when the embedding fails.

**Offline benchmark** (`latency.pipeline.test.ts`, same file on `8d0c24d`):
final → first token p50 1 700 → 1 000 ms, p95 11 800 → 2 300 ms; embedding
calls 60 → 30 for 60 questions.

**New tests:**

- unit: `latency.test.ts` (rewritten), `engineSession.latency.test.ts`,
  `latency.pipeline.test.ts`, `liveEmbed.test.ts` and
  `answer.route.test.ts`, plus recall/retriever fallback cases;
- renderer: `useful-paint.spec.ts`, which fails on `8d0c24d` (it reported
  after `**` and `-`).

**Not done.** Live acceptance needs an authorized live setup.

## M7.2b correction — consent after prefetch, Stop's denominator, paint ownership

Codex reviewed `cee0adc` and reproduced three problems. Each one has failing-before
regressions; on `cee0adc` all of them fail.

1. **[P1] Memory opt-out after a prefetch was bypassed.** Memory is now checked
   again just before the answer is sent (`revalidateRecalled`): global consent,
   the Space's switch, and each memory's eligibility, using its current text.
   It fails closed. Cases: global off, Space off, deleted, edited, and the
   non-prefetched control.
2. **[P2] Stop dropped queued questions from the sample.** The scheduler now
   reports queued jobs Stop drops (`stopped`), and they are recorded as
   `aborted` / `stopped-before-dispatch`. Deferred missed cards are recorded
   `missed` at teardown. Nothing is opened or started for them. An answer
   stopped during gathering builds no request.
3. **[P2] A stale paint could satisfy a new take.** The take now travels end to
   end: main → Cue Card (`latencyTake`) → paint report → recorder, which
   rejects a report without the take or for another one. Cue Card render
   generations void pending old callbacks.

The bounded embedding and parallel gathering are unchanged.
