# 2.3.0-preview.1 — 2026-11-19

**A Windows preview of the interview-first BrainCue.** Interviews are now the
first thing the app does, and the path through one (start, detection,
answers, follow-ups, history, Resume) was rebuilt and tested piece by piece.
This is a **preview**: the speed of answers in a real interview has not been
measured yet (see *Known limitations*).

## New

- **One Start interview.** Home leads with a single Start. The start flow
  asks for the role, then shows four rows (résumé, role and JD, audio, AI),
  each with its fix if something is missing. It also says, before you start,
  what will be sent to which provider. The role defaults to the one you last
  interviewed for.
- **A Cue Card that stays out of the way.** The current question and its
  answer take the space. Questions that were missed stay visible with the
  reason and an **Answer it** button, and earlier cards sit behind one
  toggle. The toolbar has even, labelled controls, a single Ask box, and a
  **More** panel for style, model, tools and grounding that no longer
  pushes the answer off a small window.
- **Honest model labels.** The model chips say which task they control,
  **Interview answers** or **Coding solver**, and show the model the next
  request will actually use. Each answer says which model answered it.
- **History you can trust.** Saved sessions open from this computer only,
  in the order things were said, with BrainCue's suggestions marked as not
  said. Keeping a session reports what happened to its summary and its
  memory suggestions, separately, with Retry when one fails.

## Changed

- **Questions are answered in the order they were asked**, and a corrected
  question replaces its answer instead of opening a second card.
- **Faster answers.** Memory and documents are looked up together while the
  question is still being spoken, so they're usually ready when it ends.
  That now includes "Tell me about…" and "Walk me through…", which used to
  wait for the end. A slow lookup no longer holds up the answer: after
  2.5 s it falls back to a keyword match.
- **Requests stay with the provider you chose.** Every feature routes by
  its task, and a retry never quietly moves your data to another provider.
- **Resume** goes through the same start checks, re-checks the role, and
  continues the same session.

## Fixed

- An unsaved model choice in the dashboard is no longer lost when another
  setting changes, and Save writes exactly what you edited.
- Model lists fit compact Cue Cards, and dropdowns close when you click
  elsewhere.
- Turning memory off is checked again just before each answer request is
  sent, including memories looked up early while the question was spoken. A
  request already sent can't be recalled.
- Long, unpunctuated turns stay searchable after Resume.

## Known limitations

- **Answer speed in a real interview is not yet measured.** Offline tests
  use simulated providers, so they don't measure it. The target, from the
  end of the question to the first useful words, is a median (p50) of
  1.5 s or less and a 95th percentile (p95) of 3 s or less, for General
  and short Technical questions, each measured separately. It stays open
  until it is measured on a live interview.
- The coding solver's time budget is a proposal, not yet measured.
- A document deleted while a question is being asked can still ground that
  one answer.
- Preview builds are not offered as automatic updates to the stable
  release.
